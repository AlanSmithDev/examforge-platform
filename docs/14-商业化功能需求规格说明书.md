### 1.1 开源商业化系统拆解结论（v1.1 新增，来源 lilishop / CRMEB / fuint 本地实读）

| # | 结论 | 落地条款 |
|---|---|---|
| R1 | 模板-用户券两层模型，用户券**快照冗余**（面额/折扣/门槛/范围），不回查模板 | C-2' |
| R2 | 用户券生命周期含**冻结态**：下单先占用（记订单号），支付核销；关单/退款按订单返还；"同一订单最多一张"互斥 | C-4' |
| R3 | 有效期两种模式，动态模式在**发券瞬间**计算到期并快照 | C-6' |
| R4 | 限量领取必须**条件 UPDATE 原子自增**（`claimed+1 WHERE claimed<total`），禁止先查后改；每人限领按**全状态计数** | C-3' |
| R5 | 过期处理=**每日定时 + 查询惰性**双保险；作废模板连带全部用户券 CLOSED | C-7' |
| R6 | 订单**三状态分离**（order/pay/refund），禁止单一 status | O-3' |
| R7 | 支付回调**幂等三板斧**：已支付前置判断直接返回首次结果 / 流水表存第三方单号唯一索引防重 / 返还类操作按流水去重 | O-4' O-6' |
| R8 | 退款回滚**固定顺序**：券 → 点数（流水去重+钳位不透支）→ 会员（不追讨已享受天数）→ 审计 | §8' |
| R9 | 点数流水记 `balance_after` **双值链路**，便于排查并发丢失；充值"充 X 送 Y"，赠送单独流水 | P-2' P-6' |
| R10 | 签到：连续天数昨日未签清零 + 连续档奖励 + 会员倍率；唯一索引防重复签到 | K-3' |
| R11 | 邀请：一人仅能被邀一次（invitee 唯一约束），绑定在注册事务内完成 | K-2' |

## 3. 点数/储值（REQ-P）

| 编号 | 需求 | 规则 |
|---|---|---|
| P-1 | 账户模型 | `point_account(user_id, balance, total_recharge, version)` 条件 UPDATE 防透支；**禁止先查后改两段式** |
| P-2 | 变动流水 | 每次变动写 `point_log`（充值/赠送/下载扣减/纠错奖励/券兑换/退款返还/签到/邀请/人工调整），记 `delta + balance_after` **双值链路**（R9）；充值与赠送**分两笔**（RECHARGE / RECHARGE_BONUS） |
| P-3 | 计费标准（对标组卷网并更优） | 下载一份卷：`1-10 题=1 元、11-20=2 元、21-50=4 元、51-100=6 元`（比竞品便宜 50%）；会员免费 |
| P-4 | 重复下载 | 30 天内同卷（paper_hash）重复下载不重复计费（`download_record` 表判定） |
| P-5 | 积分兑换 | 纠错采纳 +5 点、录题上架 +20 点；签到与邀请见 K 节 |
| P-6 | 充值套餐 | 后台配置"充 X 元到账 Y 点（含赠送 Z）"（fuint 模式）：50→5000(赠500)/100→10000(赠1200)/200→20000(赠3000)/500→50000(赠10000)；充值单走通用订单（skuType=POINTS） |

## 4. 优惠券（REQ-C）

| 编号 | 需求 | 规则 |
|---|---|---|
| C-1 | 券类型 | FULL_REDUCTION 满减（满 X 减 Y）/ DISCOUNT 折扣（n 折，封顶 Z）/ POINTS 兑换点数券 |
| C-2 | 券模板 | 后台创建：总量、每人限领 per_limit、领取起止时间、有效期（领后 N 天 或 固定区间） |
| C-2' | 快照 | 发券瞬间把面额/折扣/封顶/门槛/范围/名称**快照进用户券**（R1），模板后续改动不影响已发券 |
| C-3 | 领取 | 限量：`claimed=claimed+1 WHERE status=1 AND (total=0 OR claimed<total) AND 领取窗口内` 条件 UPDATE，影响行数=0 拒绝（R4）；每人限领按全状态 COUNT 校验 |
| C-4 | 核销 | 生命周期 `UNUSED → FROZEN（下单占用，记 used_order_no）→ USED（支付履约事务内核销）`；一张订单最多一张券（互斥）；核销 UPDATE 带 `status='FROZEN' AND used_order_no=?` 条件，失败整单回滚（R2） |
| C-5 | 退款返还 | 订单退款/关单时券返还 UNUSED（**仅未过期**，过期不返还）；部分履约不返还（R8） |
| C-6 | 有效期 | 领后 N 天=发券瞬间计算 `expire_at` 并落库；固定区间=直接取 `fixed_end`（R3） |
| C-7 | 过期与作废 | 每日任务批量置 EXPIRED + 查询时惰性纠正（R5）；模板作废（status=2）连带全部用户券置 CLOSED，均留审计 |

## 5. 订单与支付（REQ-O）

| 编号 | 需求 | 规则 |
|---|---|---|
| O-1 | SKU | MEMBER 会员 / POINTS 点数充值 / PAPER 单卷下载 |
| O-2 | 幂等 | 下单携带 `idempotencyKey`，`trade_order (user_id, idempotency_key)` 唯一索引，重复请求返回原单并响应头 `X-Idempotent-Replay: true` |
| O-3 | 状态机 | **三状态分离**（R6）：`status: CREATED→PAID→(REFUNDED)；CREATED→CLOSED(30 分钟超时/用户关单)`；`pay_status: UNPAID/PAID`；`refund_status: NONE/REFUNDING/REFUNDED`。非法跃迁一律拒绝（40001） |
| O-4 | 支付渠道 | `PaymentProvider` 接口：MOCK（沙箱，直接回调）/ WECHAT / ALIPAY（生产接入回调验签）；**回调幂等三板斧**（R7）：先查订单已支付直接返回首次结果 → `payment_callback(provider, callback_id)` 唯一索引防重放 → 履约事务内二次校验。**✅ 已落地（docs/22 §2.15，D14）**：官方双 SDK（wechatpay-java V3 / alipay-sdk-java）条件装配按 env 切换；接口契约 docs/17 §2.1~2.3；回调金额与订单 payCents 精确比对防篡改；查单兜底补履约。真实渠道联调待商户凭证（部署阶段） |
| O-5 | 支付成功履约 | 同一事务：订单置 PAID → 券核销（C-4）→ 开会员/加点数（含赠送分笔）→ 写流水；任一步失败整体回滚；`fulfil_json` 记录履约快照供退款回滚 |
| O-6 | 回调安全 | 回调仅接受 POST，来源校验（验签占位 + 内网白名单），金额以**服务端订单**为准，重复回调直接返回首次结果（code=42901） |
| O-7 | 超时关单 | 定时任务每分钟扫 `status=CREATED AND expire_at<now` 置 CLOSED（expire_at=创建+30 分钟），关单事务内返还 FROZEN 券；用户可主动关单（本人或超管） |
| O-8 | 退款 | 仅 SUPER_ADMIN，按 §8' 固定顺序回滚，写审计 |

## 8. 退款回滚顺序（v1.1 新增，R8 强约束）

同一事务内固定顺序，任一步失败整体回滚：① 订单 PAID→REFUNDED（非法跃迁拒绝）→ ② 券返还（未过期）→ ③ 点数回收（按 `point_log.order_no` **流水去重防重复返还**，余额不足回收钳位 0）→ ④ 会员回收 `member_until -= daysAdded`（不早于当前时间，已享受天数不追讨）→ ⑤ 审计日志。

## 10. 验收标准（单测 + 冒烟，用例细化见 docs/18）
1. 幂等：同 idempotencyKey 两次下单返回同一 orderNo 且响应头 `X-Idempotent-Replay: true`。
2. 状态机：CREATED→PAID 成功；重复回调返回首次结果（42901）；超时/主动关单后支付拒绝（40001）。
3. 券：限量领完再领报 42900(COUPON_SOLD_OUT)；每人限领按全状态计数；同券两单仅一单成功；满减门槛不足报错；订单退款券返还（未过期）。
4. 点数：余额不足扣减报 42900；充值到账=套餐点数含赠送（分两笔流水）；流水 balance_after 链路连续。
5. 计费：10 题卷 FREE 用户 needPoints=100（点）；会员 mode=MEMBER；30 天重复下载 mode=FREE_REPEAT。
6. 履约与退款：支付成功后会员到期时间正确叠加、流水成对；退款按 §8 顺序回滚且不可重复退款。

## 11. 题库数据入库契约（给另一 Agent）
- 目标表：`examforge_question.question`；字段见 `enterprise/sql/02_question.sql`。
- `stem`：LaTeX 行内式用 `\(...\)` 包裹（KaTeX 前端直接渲染），图形为 `<img src="/figures/{id}.png">`（白底清洗后由后台上传，先留占位）；
- `options`：JSON 数组 `[{"l":"A","v":"…"}]`；`analysis`：JSON `{"brief":"…","solve":"…","comment":"…"}`；
- `status=2`（上架）才会出现在前台；`difficulty 1~5`、`coefficient 0~1`；`subject_id` 参考 `subject` 表种子（高中数学=stage 3）。
- 批量插入后执行 `UPDATE question SET use_count = FLOOR(100+RAND()*900)` 模拟热度（可省略）。
