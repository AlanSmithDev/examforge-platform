## 3. 幂等与并发专项设计

- **MVP（SQLite 单写）**：并发安全以「事务内条件 UPDATE + 影响行数断言」表达——领券 `claimed+1 WHERE claimed<total`（changes=0 即售罄）、核销 `... WHERE status='FROZEN' AND used_order_no=?`（changes=0 即冲突回滚）、点数 `balance-? WHERE balance>=?`（changes=0 即不足）。断言方式见 TC-042/043/046。
- **企业版（MySQL）**：Testcontainers 拉起真实 MySQL，两个连接池同时执行领券/扣减/下单，断言 `affected rows` 合计恰为 1；回调重放用同一 callbackId 并发 POST 两次断言仅一条 payment_log。
- **回调整体幂等**：前置判断（已 PAID→42901 返回首次结果）→ `uk(channel, callback_id)` 防重放 → 金额一致性校验，三层顺序见 docs/17 §8.1。

## 4. 数据准备与种子策略

- 每次冒烟以独立进程启动（PORT=3210），测试账号全部运行时注册（手机号 `'13X'+8 位时间戳`，11 位合法），互不依赖库内既有数据。
- 优惠券用例通过 `/admin/coupons` 现场建模板（code 带时间戳后缀防重），不依赖种子券数量。
- 种子幂等：member_plan 按 code、points_package 按 id upsert 自愈；**严禁触碰 `题库/` 目录与 question 入库流程（另一 Agent 负责）**。
- 企业版：每用例事务回滚或 @Sql 清表，禁止用例间共享会员/订单状态。

## 5. CI 集成（GitHub Actions 草案）

```yaml
on: [push, pull_request]
jobs:
  smoke:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: cd code/app && npm ci
      - run: cd code/app && npm run smoke
      - if: failure()
        uses: actions/upload-artifact@v4
        with: { name: smoke-log, path: code/app/server/data/server.log }
```
