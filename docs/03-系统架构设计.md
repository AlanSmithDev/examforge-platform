## 2. 服务划分与职责

| 服务 | 职责 | 主要存储 |
|---|---|---|
| user/auth | 注册登录（手机号/微信/学校批量导入）、JWT 签发、RBAC | MySQL(user 库)、Redis |
| member/pay | 会员、点数账户、订单、支付回调、开票 | MySQL(member 库) |
| question | 题目 CRUD、筛选、试题篮、纠错、知识点树、审核工作流 | MySQL(question 分片)、ES |
| figure | Figure DSL 管理、Schema 校验、SVG/PNG 渲染、图形模板库 | MySQL(figure)、OSS |
| media | 文件上传、图片预处理（裁白边/增强）、OCR 调度、防盗链签名 | OSS、Redis |
| paper | 蓝图、智能组卷引擎、试卷 CRUD、平行卷、细目表 | MySQL(paper)、Redis |
| render | 排版引擎（HTML 模板→PDF/Word）、答题卡生成、异步任务 | MQ、OSS |
| search | 题目搜索（全文+筛选+向量混合）、搜题记录 | ES 8 |
| ai-gateway | 多模型路由（DeepSeek/Qwen/GLM：私有 vLLM 优先、云 API 兜底）、配额、AIGC 审核 | Redis(配额)、MySQL(日志) |
| ai-tutor | AI 出题/变式、解析生成、AI 讲题（SSE）、知识点自动标注 | LLM、MQ |
| rag-svc | 题库向量化、Milvus 检索、重排、RAG 问答 | Milvus、ES |
| practice/wrong/report | 作业布置、练习记录、错题本、学情报告 | MySQL(practice)、ClickHouse(行为分析) |
| school | 校本题库空间、备课组协作、批量账号 | MySQL(school) |
| message | 站内信/短信/小程序订阅消息（下载完成、审核结果） | MQ、MySQL |

**跨服务规约**：服务间 OpenFeign + 注册中心 Nacos；强一致场景（扣点数+订单）用本地消息表+MQ 最终一致，Seata AT 仅兜底；所有服务无状态，会话全在 JWT+Redis。

## 3. 容量估算（3000 万注册用户）

### 3.1 流量模型
| 指标 | 数值 | 依据 |
|---|---|---|
| 注册用户 | 3000 万 | 目标 |
| MAU / DAU | 900 万 / 100 万（均值） | 教育类工具 30%/3.3% |
| 峰值 DAU | 350 万 | 开学季/高三模考周/晚 20:00-22:30 |
| 峰值读 QPS | 12,000（列表+详情+静态） | 峰值 DAU×人均 30 次内容请求÷集中 2.5h，×1.2 冗余 |
| 搜索 QPS | 2,000 峰值 | 人均 1.5 次搜索/日 |
| 写 QPS | 800 峰值（组卷操作/练习提交） | 写读比约 1:15 |
| 智能组卷 | 峰值 50 次/分钟 | 单次计算 <8s，paper-svc 8 副本可扛 |
| 导出任务 | 峰值 3,000/小时 | 异步队列，按优先级调度 |
| AI 讲题 | 峰值 200 路并发流式 | GPU 节点按路扩容 |

### 3.2 存储模型
| 数据 | 规模 | 方案 |
|---|---|---|
| 题目主表 | 2,000 万题起步，年增 300 万 | MySQL 分片：16 库 × 64 表，路由键=subject_id+question_id |
| 题目内容(JSON+LaTeX) | 平均 6KB/题 ≈ 120GB | 与主表同分片；大解析(>16KB)拆 detail 表 |
| 图片（上传题） | 5,000 万张 ≈ 25TB(处理后 8TB) | OSS 双份（原图+清洗版）+ CDN |
| 图形 DSL/SVG | 800 万个图形 | DSL 存 MySQL，SVG/PNG 缓存存 OSS |
| 试卷 | 5,000 万份 | paper 库分片（user_id 维度） |
| ES 索引 | 题目 2,000 万文档 ≈ 60GB + 向量字段 | 6 节点(3 data×2 副本) |
| 练习/行为日志 | 日增 2 亿行 | ClickHouse + Kafka，90 天热/冷归档 OSS |

## 4. 高并发设计（对标 damai/12306 的打法）

### 4.1 多级缓存体系
```
浏览器/CDN(静态+已渲染题目HTML片段,immutable) 
  → Caffeine 本地缓存(知识点树/学科配置/热门题目Top1万, 30s~5m)
  → Redis Cluster(题目详情/试卷/用户点数, TTL+逻辑过期防击穿)
  → MySQL(分片+读写分离)
```
- **题目详情**：key=`q:{subject}:{id}`，命中率目标 99%（教育内容读多写少，天然适合）；缓存对象为**服务端预渲染的 HTML 片段**（公式 KaTeX HTML + 内联 SVG），前端零渲染成本 —— 这是内容站高并发的关键：**把渲染成本从客户端移到写路径**。
- 缓存更新：题目审核通过/纠错生效时发 MQ 事件 → 缓存刷新服务消费 + 延迟双删； binlog(Canal) 兜底对账。
- 防击穿/雪崩：逻辑过期+互斥重建；TTL 加随机抖动；知识点树等配置类缓存永不过期+主动刷新。
- 热点探测：打卡点统计 TopN（模考季某真题爆火），本地缓存强制驻留（借鉴京东 hotkey 思路）。

### 4.2 异步化与削峰（组卷/下载/AI 全部任务化）
| 场景 | 方案 |
|---|---|
| 智能组卷 | 同步返回 taskId，RocketMQ 顺序队列计算，前端轮询/SSE；免费用户低优先级队列 |
| 导出渲染 | 延迟消息+优先级队列（会员优先），重试 3 次死信告警；渲染结果 OSS+CDN 复用（同卷同配置命中缓存直接返回） |
| AI 出题/讲题 | 讲题 SSE 直连 ai-tutor；出题走队列；全链路 token 配额桶（用户级+系统级） |
| 搜索日志/埋点 | Kafka → ClickHouse，不打主链路 |

### 4.3 数据层
- **分库分表**：ShardingSphere-JDBC；question 按 `subject_id % 16` 分库、`question_id % 64` 分表；paper 按 user_id； practice 按用户+时间。分布式 ID：雪花变体（借鉴 damai id-generator-framework：时间戳+机器位+序列）。
- 读写分离：题目读流量 80% 走只读实例；主库仅写+强一致读。
- 冷热分离：2 年前的练习明细归档 ClickHouse/OSS(Arrow)，题目不冷（长尾价值高）。
- 查询纪律：题目筛选全部走 ES，MySQL 只做主键/二级精查；禁止跨分片 join（试卷-题目以宽表/冗余解决）。

### 4.4 限流、熔断、降级矩阵
| 接口 | Sentinel 规则 | 降级预案 |
|---|---|---|
| 题目搜索 | QPS 2000/节点集群流控 | 返回缓存的热门筛选结果 |
| AI 讲题 | 用户级 20 次/日(免费)/会员200，并发 200 路 | 排队+提示高峰 |
| 导出 | 集群 500 并发任务 | 队列延迟+通知 |
| 详情页 | 无需限流(缓存扛) | 静态兜底页 |
| 游客详情 | 30 次/时/IP | 登录引导 |
全站：网关层 CC 防护+人机校验(验证码/行为)；核心指标 5 分钟异常自动熔断非核心依赖（学情报告、推荐）。

## 5. AI 平台架构

```
业务服务 ──→ ai-gateway(统一SDK: 提示词模板/超时重试/降级/成本记账/AIGC审核)
              ├─ 模型路由: 私有 vLLM(Qwen2.5-72B-数学增强 / DeepSeek-Math) 优先
              │            云 API(DeepSeek/Qwen-Max) 兜底与高难度任务
              ├─ 出题流水线: 考点约束 → LLM 生成 → 符号校验(SymPy 验算答案) 
              │            → 查重(向量+文本) → 人工审核队列
              ├─ 讲题: SSE 流式 + 分步结构化输出(步骤/公式/图形指令)
              └─ RAG: 题目→ embedding(bge-m3) → Milvus + ES 混合检索 → 重排 → 生成
```
- 数学可靠性：AI 生成的计算题必须过 **SymPy 数值/符号验算** 才进审核队列，杜绝 AI 算错答案上架。
- 成本：私有 GPU（2×A800 起步，vLLM 量化）承担 70% 流量；token 记账到用户/功能维度，看板周报。
- AIGC 合规：生成内容显式标识、留存 prompt/输出审计 6 个月、接入内容安全审核。

## 6. 数学公式与图形的架构位置
- **figure-svc** 为独立渲染服务：输入 Figure DSL(JSON) → 输出 SVG（Web 用，进 OSS+CDN，immutable URL）与 300dpi PNG（打印用）；Puppeteer/resvg 池化 Worker（K8s HPA 按队列深度扩容）。
- **render-svc** 导出管线：结构化试卷 → HTML 模板(公式/图形已预渲染) → Puppeteer 出 PDF；Word 走 docx 生成 + LaTeX→OMML 转换。
- 详见《06-数学图形与公式解决方案》。

## 7. 高可用与部署
- 环境：dev → test → staging(影子流量) → 生产；生产 K8s 双可用区，核心服务 ≥3 副本跨 AZ。
- 数据库：两地三中心（主库同城主备 + 异地灾备延迟复制）；Redis 主从+哨兵→Cluster 三主三从×2 AZ；ES/`RocketMQ` 跨 AZ 部署。
- 发布：金丝雀 5%→25%→100%，全链路压测（影子表）例行化，预案演练（缓存雪崩/ES 故障/CDN 故障/LLM 供应商故障）每季度。
- 混沌工程：定期杀节点验证降级；核心 SLO 看板对外（教师端可用性）。

## 8. 安全架构
- 认证：JWT(15min)+Refresh Token；B 端 SSO（企业微信/钉钉）。
- 内容防盗：下载链接签名 URL（5 分钟有效）、导出 PDF 教师版水印（用户 ID 隐写）、接口防爬（行为指纹+速率）、图片 CDN 防盗链 Referer+签名。
- SSRF 防护（验收硬指标）：所有服务端发起的 URL 抓取（图片代理、回调、webhook）必须：仅 https、域名白名单、解析后校验 IP 非内网/环回/链路本地段，DNS 重绑定防护。
- 数据合规：学生信息最小化、手机号加密存储（AES+KMS）、操作审计、等保三级测评。
