## 1. 邀请裂变与新人礼包（K-1/K-2）

| 编号 | 需求 | 规则 |
|---|---|---|
| I-1 | 邀请码 | 注册成功自动生成 6 位 base36 唯一邀请码（`user.invite_code`），个人中心可见 |
| I-2 | 受邀注册 | 注册携带 `inviteCode` → `user.invited_by` 记录邀请人 id；邀请码无效不阻断注册（静默忽略） |
| I-3 | 新人礼包 K-1 | 注册成功即 +10 点（reason=NEWBIE，经 trade 内部奖励接口发放） |
| I-4 | 邀请奖励 K-2 | 受邀注册成功后邀请人 +20 点（reason=INVITE）；**自邀无效**（inviteCode 归属校验=本人则不发） |
| I-5 | 防刷 | 同一受邀人只发一次（注册幂等）；奖励走 trade 原子加点+流水；异常 fail-open 不阻断注册 |
| I-6 | 接口 | 注册接口扩展 `inviteCode` 字段；`GET /api/v1/users/me/invite` 返回我的邀请码与已邀请人数 |

## 3. AI 搜（对标菁优 AI 搜并超越）

| 编号 | 需求 | 规则 |
|---|---|---|
| S-1 | 意图解析 | 自然语言 → 结构化筛选 `{keyword, subjectId, type, difficulty}`：MOCK 通道用规则解析（难度词/题型词/知识点词），真实通道用 LLM 输出 JSON（超时/失败降级 MOCK 解析） |
| S-2 | 检索 | 解析结果调题库检索（ES 启用走 ES，未启用走 LIKE），返回题目卡片（含题干/难度/知识点） |
| S-3 | 兜底 | 解析失败 → 全文关键词直搜；0 结果 → 提示"AI 出同款"入口（已有 /ai/generate-question） |
| S-4 | 接口 | `POST /api/v1/ai/search {query}`；教师端新增搜索页（结果可加入试题篮/看详情） |

## 3A. 拍照搜题（AI 搜的图片输入通道，docs/22 C7）

> 定位：与 §3 文本 AI 搜共用检索底座（S-2 统一检索、S-3 兜底），新增「图片 → 题干文本」的视觉入口。
> 实现落位：examforge-ai（`PhotoSearchRules` 纯规则 + `AiService.photoSearch` + `POST /api/v1/ai/photo-search`）；网关 `/api/v1/ai/**` 路由复用，零改动。

### 3A.1 处理链路

```
拍照/选图（前端 FileReader → base64 data URL）
  → POST /api/v1/ai/photo-search {imageBase64, mime?, hint?}
    → 图片校验（PhotoSearchRules.validateImage：jpg/jpeg/png/webp、解码后 ≤ 8MB）
    → AI 视觉提取题干（chatVision；MOCK Provider 按提示词含"题干"标记返回确定性伪题干，保证链路离线可演示）
    → 题干 → 检索关键词（PhotoSearchRules.extractKeywords：停止词切分 → 纯中文连续段 → 长度夹取 [2,12] → 去重保序 → ≤6 个）
    → 题库检索（复用 /internal/questions/search，ES 优先降级 LIKE；按关键词序逐词尝试，前 3 词内首个非空即止）
    → 匹配度重排（PhotoSearchRules.matchScore = 候选题干命中关键词数 / 关键词总数；rerank 降序、并列稳定）
  → 候选题目卡片列表（含 matchScore）
```

### 3A.2 请求 / 响应契约

请求 `POST /api/v1/ai/photo-search`（登录，网关注入 X-User-Id）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| imageBase64 | string | 是 | 图片 base64，允许带 `data:image/*;base64,` 前缀（后端剥离）；解码后 ≤ 8MB |
| mime | string | 否 | `image/jpeg|png|webp`；未传时从 data URL 头解析，均无则 42200 |
| hint | string | 否 | 识别失败时的文字补充（题干文字），触发降级检索 |

成功响应（识别命中）：

```json
data: { "recognized": true, "provider": "MOCK", "degraded": false, "costMs": 12,
        "stem": "已知函数 \\(f(x)=\\ln x-ax\\) 有两个零点，求实数 \\(a\\) 的取值范围。",
        "keywords": ["函数", "两个零点", "实数", "取值范围"],
        "count": 3,
        "list": [ { "id": 12, "type": "解答题", "difficulty": 4, "coefficient": 0.6,
                    "kpNames": "函数与导数", "stem": "…", "matchScore": 0.75 } ] }
```

### 3A.3 降级矩阵（流程不断原则）

| 场景 | 行为 | 响应标记 |
|---|---|---|
| Provider 无视觉能力（UnsupportedOperationException，如纯文本模型） | 不调用视觉，直接走降级 | `recognized:false, degraded:false` |
| 视觉调用异常（超时/网络） | 降级 MOCK Provider 重试一次 | `degraded:true` |
| 视觉返回 recognized=false 或 JSON 解析失败 | 有 hint → 文本规则解析检索（同 S-3 兜底口径）；无 hint → 引导文案 | `recognized:false, hintUsed:true`（有 hint 时） |
| MOCK Provider | 提示词含"题干"标记 → 确定性伪题干（扫描转录场景不受影响，仍返回未识别驱动人工转录） | `recognized:true`（演示链路） |

校验失败：`42200`（`data` 为可直接展示的中文文案：仅支持 jpg/png/webp / 图片超过 8MB 上限 / imageBase64 必填）。
配额超限：`42900`（**拍照搜题计入 AI 配额**——每次含一次视觉调用，与文本 AI 搜不计费的口径不同；免费 20 次/日、会员 200 次/日，`examforge.ai.quota-*-per-day` 可配）。
治理：每次调用落 ai_log（scene=`PHOTO_SEARCH`，promptChars 记 base64 体积便于视觉调用量核算）。

### 3A.4 关键词规则口径（无分词器的轻量实现，确定性可测）

- 停止词表（题干高频虚词/套话，如 已知/求证/下列/的/在/求…）**当分隔符**使用，而非仅删除——顺带完成粗切分；
- 仅保留纯中文连续段（公式 `f(x)=x²-2ax+1`、数字、拉丁字母整体丢弃），单字词丢弃（区分度差），长度夹取 [2,12]；
- 已知取舍：不收"则/且/中"等高风险单字（会切碎"规则/并且/中心"等实义词）；接受轻微过切分，LIKE 检索对短词仍可命中。

## 4. 验收
- 邀请：新用户带有效邀请码注册 → 双方点数到账、流水可查；重复/自邀不发。
- 看板：聚合数值与各库 COUNT 一致。
- AI 搜："高二 立体几何 解答题 较难" → 命中题目列表；"随便来点导数题" → keyword 导数。
- 拍照搜题（§3A）：MOCK 渠道 → 确定性伪题干 → keywords=[函数,…] → 检索命中且按 matchScore 降序；识别失败 + hint → 文字降级检索；纯文本 Provider → 引导文案（流程不断）。
